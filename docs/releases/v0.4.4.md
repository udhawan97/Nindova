# Nindova v0.4.4 — Kept Nights

Nindova v0.4.4 gives the Night Room Session one owner for the two rules that decide how a Session ends and how it resumes, and closes a way a Session could end without keeping the Night it had just been played for. Authored behavior, pacing, and content are unchanged.

## Highlights

- A Session that reaches the fifteen-minute cap while still settling now completes its final response and records the Night before the return to Rest. Every Session phase has an answer at the boundary, including the settling phase, which had none.
- Version-4 same-tab resume validation is decided in one place, without the DOM: schema, Board profile, board-identity re-derivation, settled-Tile membership and reachability, phase-and-ending agreement, and the clock audit each return one refusal reason, and a stored record can no longer make the Night Room fail to open.
- The Masala Mound is the single authority for the nine kitchen forms. Local memory validates a stored completion against the vocabulary the board deals rather than a second hand-maintained list, and an unused nightly-recipe path that could never produce a board this product deals was deleted.
- The Dawn keepsake frame lives beside the rest of Dawn, leaving the Session surface to host the canvas and its export. The rendered keepsake is unchanged.
- The Session surface fell from 963 to 743 lines and no longer decides closure or resume for itself.

## Evidence boundary

The release gate covers 140 deterministic unit tests, up from 107; the full rendered browser suite including both PWA and standalone surfaces; a resumed settling Session proven to record its Night and clear its stored record, with that regression test verified to fail without the fix; the Dawn keepsake canvas proven byte-identical before and after its move on both the remembered Rasoi Night and the migrated legacy record; and rendered phone and desktop surfaces with keyboard-only and reduced-motion paths.

Automation does not establish human enjoyment, calmness, sleep or memory benefit, real-device VoiceOver or TalkBack acceptance, installed Safari or broader Android PWA behavior, or the fifteen-minute wall-clock run, which the repository excludes from routine checks.

## Notes

`session.ts` still compiles under a relaxed TypeScript project; the two extracted modules joined the strict one. The Session module boundaries are not yet recorded as an architecture decision.

The native iOS Wall remains deferred. No state schema, authored content, score, streak, rank, visible timer, collection, randomized reward, assessment path, analytics, app telemetry, or third-party runtime request was added.
